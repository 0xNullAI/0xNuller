# DG-Chat · FAQ / 故障排查

## 常见问题

### 我能加入吗？

- 浏览器是 Chrome / Edge / Bluefy（iOS）/ Kiwi Browser（鸿蒙）？
- HTTPS 或 localhost？
- 房间号对吗？
- 网络能通：PeerJS signaling 走 wss://；某些公司/学校/咖啡厅网络可能屏蔽 WebRTC

### 连上房间但看不到对方设备状态

- 对方也连了设备吗？没连的话他的成员卡片显示「无设备」状态
- WebRTC 数据通道偶尔会断，刷新页面试试

### 远程控制时滑块卡顿

- 网络延迟大；强度变化是相对调整，每 100ms 一个 BLE tick，单 tick 内多次拖动会被合并
- 极端情况可以让对方先停下、再慢慢拖

### 我能听到/看到队友吗（语音/视频）

- 不能，DG-Chat 只做文字聊天 + 设备控制
- 想要语音视频请用 Discord / Telegram 等专业工具，DG-Chat 跟它们不冲突

### 被控制的时候我能取消吗

- 随时。点你自己卡片 → 进自己的控制界面 → 调上限到 0，或断开蓝牙
- 也可以直接关浏览器标签页

### 我导入的波形别人看得到吗？

- 不会自动同步。波形保存在你浏览器 localStorage，仅你可见
- 如果想让朋友用你的波形，可以：先选好那个波形，然后把控制权交给朋友——朋友能用到你正在播放的波形
- 或者把 `.pulse` 文件直接发给朋友让他自己导入

### 房间号怎么生成 / 是否会重复？

- 房间号由 PeerJS 服务端分配，全局唯一
- 但 PeerJS 默认会回收闲置 ID。如果一个房间长时间没人，号就被释放了

### 房间最多多少人？

- 没硬性限制。WebRTC mesh 连接数上去之后浏览器会卡，建议 ≤8 人

### 切到后台输出会停吗？

- 默认会（"后台行为：停止"）
- 设置里可以改成「保持」，DG-Chat 用 Web Worker 模拟独立 tick，理论上抗节流，极端情况仍可能卡顿

### 关浏览器后再开还能进同一个房间吗？

- 房间号一样就行（如果还在）
- 但聊天记录是 P2P，没人留就丢了。这是设计——零数据保留

## 故障排查

```
症状                            → 排查方向
─────────────────────────────────────────────────
房间号输入后一直转圈              → signaling 连不上，换网络
对方进来了但看不到设备            → 对方没点蓝牙连接
设备已连，但远程操作没反应         → 看本地控制是否正常；不正常说明蓝牙断了
强度滑块拖不动                  → 通道未启动 / 撞到上限
切到后台后输出停了               → 这是默认行为，可以改设置
P2P 一直 connecting...         → NAT 穿透失败，换网络或开 VPN
```

## 跟其他 DG 项目并存

| 我同时想用 | 是否可行 |
|---|---|
| DG-Chat + DG-Agent 同浏览器 | ❌ 蓝牙连接排他 |
| DG-Chat + DG-Agent 不同浏览器 / 不同设备 | ✅ |
| DG-Chat + DG-MCP | ❌ 同上 |
| DG-Chat + 官方 App | ❌ 同上 |
| DG-Chat 在 A 浏览器，DG-Agent 桥接 IM 不连蓝牙 | ✅ DG-Agent 不连蓝牙时不冲突 |

总规则：**同一时间，一台郊狼只能被一个客户端蓝牙连接**。

## 故意设计的限制

- **聊天不持久化**：刷新或关页面，本机看到的聊天就没了。零数据保留是底线
- **波形不自动同步**：避免推送过来意料外的波形被立刻播放
- **远端不能突破本地上限**：协议层强制
- **房间号是公开的**：知道房间号就能进，私密性靠你不分享而非靠系统
