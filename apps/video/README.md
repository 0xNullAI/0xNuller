# 0xNuller Video

Video 会持续观察摄像头的最新画面，按当前角色与可选场景进行简短叙述。没有连接设备时可只进行视频陪伴；
连接设备后，才可在用户授权范围内控制已连接设备。

## 如何使用

1. 在「软件设置 → AI → Video」配置支持图片输入的模型。
2. 在 Market 导入角色并打开角色聊天；可给这段聊天绑定已导入的场景卡。“管理”按钮可打开个人内容。
   场景只提供环境，不能单独成为拥有对话的角色。
3. 若需要设备互动，可连接一台或多台郊狼或负鼠。连接列表只表示 AI 可选择的目标，不会自动产生输出。
4. 选择摄像头、运行时长和观察间隔，并决定是否允许增强或脉冲。
5. 点击“开启视频陪伴”或“开启设备互动”。运行中可以暂停、继续或紧急停止。

## 运行时会发生什么

- 摄像头每秒更新一次内存中的最新画面；模型按选定间隔处理。模型忙碌时，新画面会替换尚未处理
  的旧画面，所以不会积压越来越长的图片队列。
- 纯陪伴观察不请求设备控制权，也不向模型提供任何设备工具；文字观察仍写入当前私人会话。
- 镜头开启后可直接给角色发文字消息。用户消息先保存到同一服务器聊天，模型再结合当前单帧和近期聊天作答；
  回答先暂存在服务器的会话外，当前账号与视频问答仍有效时才确认为普通角色消息。取消会撤销未确认回复；
  如果取消与确认同时发生而无法核实结果，界面要求重新打开原会话核对，避免重复发送。未确认草稿不会进入
  聊天记录、记忆、搜索或备份，并在十分钟后由服务器清除正文。每条提问按当前问题重新检索这段关系的私人记忆，避免只依赖镜头开启时的快照；
  关系绑定不匹配时停止回答。重新进入时从服务器显示最近 12 条普通聊天消息。问答期间自动观察会暂停，
  用户可手动继续。视频问答不提供设备工具。
- 视频输入栏复用 Agent 的语音识别设置，点击语音按钮后听写，停止后先填入可编辑草稿，用户确认才发送；
  关闭摄像头、离开页面或切换账号会中止识别。未开启语音识别或浏览器不支持所选方式时会显示原因。
- 视频问答回复和最新陪伴观察均可点击朗读按钮按需播放。默认复用 Agent 的浏览器／自带代理语音设置；自带代理由用户自行承担服务商费用，不走平台 Credit。Video 高级选项可明确选择托管朗读：每条先显示最高 Credit 并由用户确认，服务端按 CosyVoice 返回的真实字符数结算；生成完成后需再点击一次才播放。新观察到达、切换账号、关闭摄像头或离开页面立即停止旧播放。朗读不新增聊天消息；临时音频最多保留 24 小时，不进入长期记忆。
- AI 会看到当前授权的每个物理输出实例。即使两台设备名称相同，它们也有不同的内部目标 ID。
  每次动作只控制一个明确目标和通道，不会把同一指令广播给全部设备。
- 从一台设备或通道切换到另一台之前，系统先停止旧目标。设备断开、重连或运行时身份改变后，旧授权失效。
- 强度、增量、持续时间和短时输出租期始终受「设备与安全」设置限制。允许增强只是在这些上限内开放
  小步增加，不会绕过权限或安全策略。
- 场景只决定叙事风格，不能覆盖 Video 的连续观察、安全或工具结果规则。工具请求不等于执行成功；
  设备动作必须返回与本次动作相符的可核实结果；结果缺失或不匹配会撤销授权并请求全局停止。
  同一画面返回多项动作时，后续任何一项参数非法或工具越权也会撤销整批授权并请求全局停止，
  防止先前已启动的输出留在运行状态。
  有设备动作的观察只显示程序生成的执行说明，不把模型在执行前写的成功说法当作结果。

## 隐私与停止

图片不会写入会话历史、浏览器存储、账户同步、导出或日志。暂停、结束、切换模块、隐藏页面、摄像头
结束、设备断开、授权到期、观察超时或连续模型失败都会停止当前控制。紧急停止覆盖所有已连接输出；
如果系统无法确认停止成功，会保持安全锁定并提示用户断开设备。

网页摄像头需要 HTTPS 或 localhost。Android 由应用请求系统相机权限。

## 维护者须知

Video 应用只保留视觉帧调度、一次性授权、观察节奏、失效停止和界面展示。共享场景来自
`@0xnullai/scenes`，输出身份来自 `@0xnullai/device-runtime`，模型调用与设备安全执行复用
`packages/agent`。不要在应用中复制 provider、设备身份、权限或安全上限逻辑。

统一 Web 中的用户操作说明见 [`apps/web/src/docs/video.md`](../web/src/docs/video.md)。

## 与私人对话衔接

文字对话中的「摄像头观察」入口沿用当前会话、公开角色卡和私人关系。启动 AI 观察前读取
服务器近期文字和已确认记忆；无登录仍可预览摄像头，但不能开启需保存记录的 AI 观察。
若服务器会话绑定了可选场景，只将已导入的场景环境 Prompt 叠加到原角色；场景缺失会在
启动 AI 观察前报错，不会更换角色或把观察存入别人的会话。
完成的文字观察以独立消息 ID 进入同一服务器会话；原始帧不进入会话、日志或浏览器存储。
提交观察后若用户取消，客户端会立即向服务器撤销同一观察 ID；服务器以取消墓碑阻止迟到的提交，并删除已提交的观察。
只有收到撤销确认才能确认服务器未保留该观察。断网或切换账号导致撤销请求不能完成时，客户端会停止当前控制并报告保存状态未确认；重新联网后仍需核对该会话记录。
服务器将最终文字标为 `camera_observation` 事件，聊天时间线单独显示；普通 AI 对话不把它
当作角色曾向用户作出的承诺。服务端只能证明事件由登录账号通过观察接口提交，不能证明
实体摄像头或画面内容的真实性。
服务器保存失败会停止当前控制，不回退本地历史。账户切换停止观察、关闭摄像头并清空私人上下文。
一次观察开始后，模型提示固定为该服务器对话准备的角色或场景卡及私人上下文；其他页面的 Market
选择变化不会把观察切换到另一张卡，暂停恢复仍沿用本次提示。新的观察才读取新的选择。

Video 工作台负责摄像头观察与设备互动。角色视频生成在同一私人聊天的「聊天设置 → 生成图片与视频」中提交异步任务，生成状态与结果回到聊天时间线；两者不是实时视频通话。托管 `vision` 每次观察先最多预留 59 Credit，最终按上游真实 Token 用量扣费；页面先从托管模型服务读取报价，报价不可用时不启动托管观察。自带密钥时使用“自定义” OpenAI 兼容接口，须由用户打开「支持图片输入」，由服务商计费，不经过平台 Credit。托管模型只发送压缩后不超过 250 KiB 的单张 JPEG，最短观察间隔 5 秒、单请求不重叠；原始画面不留存。价格和失败待核对规则见 [托管模型服务](../../workers/llm-proxy/README.md#摄像头视觉-credit)。

The camera workbench includes an explicit opt-in 2D character portrait overlay. It uses the private
relationship's server-saved appearance; the overlay is DOM-only and never enters captured frames,
model inputs, or saved observations. No 3D avatar, face anchoring or spatial tracking is claimed.

在支持 WebXR `immersive-ar` 与 `hit-test` 的 HTTPS 浏览器/设备上，Video 设置页提供独立的
「进入 AR 放置」按钮。点击后浏览器才请求沉浸式 AR 会话；对准真实平面并点按画面，可将当前
私人关系头像（无头像时使用公开头像或默认符号）放置在跟踪空间中，再次点按可重新放置。
它是空间放置的 2D 立牌，不是 3D 人物、面部捕捉或口型同步。退出、隐藏页面、切换账号或角色
会结束会话；图像只在当前页面和 WebGL 纹理中使用，不上传或写入摄像头观察帧。
不支持 WebXR 的浏览器明确显示 2D 回退，不请求摄像头权限。真实空间跟踪及放置效果仍需在
支持 WebXR AR 的实体设备上验收。

浏览器适配依据：[WebXR Device API](https://immersive-web.github.io/webxr/)、
[WebXR Hit Test Module](https://immersive-web.github.io/hit-test/) 与
[WebXR DOM Overlays Module](https://immersive-web.github.io/dom-overlays/) 的工作组规范。
