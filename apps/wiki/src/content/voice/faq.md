# DG-Voice · FAQ / 故障排查

## 现在能用吗？

**部分能用。** v0.1.0 完成的是设备连接 + 完整安全链，都有测试覆盖、能真实跑通。**实时语音通话本身还没接通**——首页那个通话区块目前是占位符。如果你要找一个现在就能语音对话的方案，先用 [DG-Agent](#/agent/manual) 的按住说话功能。

## 为什么不直接在 DG-Agent 里加实时语音？

DG-Agent 的 Agent 循环（`AgentRuntime.runToolLoop()`）是请求/响应式的回合制：转一句话的文本、跑一轮工具调用、拼句子喂 TTS。实时语音是长连接上由服务端驱动的双工流，"什么时候说话"这件事完全交给 provider——两种形态在循环这一层是不兼容的架构，硬塞进同一个代码库只会让两边都变形，所以拆成独立项目。

## 为什么选了这几个语音 Provider（xAI / OpenAI / Azure / 智谱），没有 Gemini / Deepgram / ElevenLabs？

筛选条件是：双向实时语音 + 会话中工具调用 + 运行时下发工具 + 浏览器直连（不需要中继服务器）+ 适配代码量小。逐个排除原因：

- **阶跃星辰 / 阿里 Qwen**：协议本身合适，但换票/鉴权环节需要服务端中转，不符合"无服务端"的硬约束
- **Google Gemini Live**：最便宜，但事件形状差异太大，估算需要 400-700 行适配层
- **Deepgram**：二进制帧协议，估算 600-900 行适配，且中文 TTS 支持不好
- **ElevenLabs / Hume**：工具必须预先注册在服务端 agent 配置里，浏览器无法运行时下发——DG-Voice 的工具集取决于当前连了哪些设备，这是结构性不兼容，不是适配量的问题

## 需要自己搭后端吗？

不需要。DG-Voice 是纯静态站点（Cloudflare Worker 只做静态资源托管），语音音频和工具调用票据都是浏览器直接跟你选的 provider 交互，用你自己的 API Key。

## API Key 安全吗？

Key 只存在你自己浏览器的 localStorage 里，不会经过 DG-Voice 的任何服务器（因为根本没有服务器逻辑）。风险跟你在任何纯前端应用里填 API Key 是同一个模型——浏览器本地存储的通用风险，不是 DG-Voice 特有的。

## 支持哪些设备？

跟 DG-Agent 一样的四种：郊狼 Coyote（电击）、负鼠 Opossum（振动）、爪印 paw-prints（按键传感器）、灵猫边缘控制 civet-edging（压力传感器），可以任意组合同时连接。设备层直接来自 [`@dg-kit/*`](#/kit/overview) 1.13.0，跟 DG-Agent/DG-Chat 是同一份实现。

## 安卓版什么时候有？

还没开工，计划复用 DG-Agent/DG-Chat 已验证的 Tauri 安卓壳。已确认技术上可行（麦克风权限、WebView 安全上下文都验证过），但"锁屏就挂断通话"是 v1 会采取的安全默认——真正的后台续航通话需要安卓前台服务，且上游 Tauri 有个未合并的白屏 bug，这块单列为后续工作。
