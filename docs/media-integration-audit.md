# 网站语音、视觉与 Credit 整合审计

本页记录 develop 重构起点的代码事实、最小整合路径与尚未交付项。产品需求以
[陪伴平台升级计划](companion-platform-plan.md) 为准。本次已补充服务器会话及托管 Voice 持久化结算底座，未上线新媒体服务。

## 已有链路

| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |

**余额账本已统一，产品入口、费用语义与会话身份尚未统一。** `workers/auth/src/index.ts` 的
`reserveVoiceCredits` / `settleVoiceCredits` / `releaseVoiceCredits` 最终调用同一套
`reserveCredits` / `settleCredits` / `releaseCredits` 与 `credit_ledger`、`credit_reservations`。
无需新增一套音视频钱包。文字使用 Token，Voice 使用连接时长，两种计量可以保留，但应由统一的
价格目录、预留/实扣/退还展示及用量关联管理。

当前 Video 是摄像头观察和受权设备控制，**不是**角色视频生成或人与 AI 视频通话。
后两项必须另列能力、价格、任务与素材生命周期，不能仅复用 Video 名称后宣称已完成。

## 最小改动方案

1. 在服务器个人会话层统一 `conversationId`、`relationshipId`、`characterRevision`、
   `turnId`、`mediaSessionId`；所有文字、语音字幕、主动消息和媒体任务都关联同一私人关系。
   公开角色定义与私人人设称呼/记忆分开。设备的本机 session/lease/targetId 不迁移为这些服务器 ID。
2. 网站聊天框增加文字、通话、摄像头与生成素材入口。现有 Voice / Video 的工作台、设置与管理
   页面保留。外壳组合它们，共享行为下沉到 platform/agent；功能 app 之间不相互导入。
3. 先接入 Voice 完成字幕的幂等服务器写入和服务器 context 读取，再加入个人人设、最近对话摘要、
   中期事件、长期记忆和关系历史。流式半句话不进入长期记忆；失败/取消不能成为已发生的关系事实。
   本次尚未新增该服务端接口。
4. 实时 WebSocket 与文字 HTTP 保留各自协议适配，统一的是账户、能力目录、会话上下文与计费。
   新建 API gateway 可以作为稳定外层路由；现有 LLM Worker 与 Voice DO 仍为执行者，逐项切换，
   不把 Realtime 事件硬塞进文字 client。上游密钥只由服务器管理，供应商/model/price 由白名单决定。
5. 视觉托管必须增加有图像能力的独立模型条目、真实图片成本计量、请求限额与对应服务端适配，再
   在视觉 profile 开放。现有文字档位不能通过放宽前端检查冒充视觉模型。
6. 生成图片（含「让角色出镜」，已取代情境自拍；视频生成已取消）走持久化任务：预留 → 执行 → 结果确认 → 结算；失败释放、回调
   验签、任务/幂等键去重、断线恢复及超时补偿先于上线。消费明细关联聊天气泡与任务。
7. 真人群聊复用现有 Chat 的参与者和可见性权限，新增语音/媒体消息与角色发言类型。私聊 memory
   不因进群而公开；仅用户明确分享的内容可成为群上下文。媒体分享需明确选择，摄像头原始帧继续
   保持不持久化；设备工具仍经过原有 owner-side 权限边界。
8. 创作者仅获得平台使用 Credit，不做提现、现金分成、收款或结算账户。复用现有余额和账本，
   奖励需有来源事件和幂等记录，后台保留原管理入口。

## 计费可靠性发现

- 已修复：上游连接失败后，`releaseVoiceCredits` 抛错会跳过 `active = 0`，账户被误判一直在通话。
  现在先恢复本地状态，再尝试释放；失败输出不含票据的事件日志，允许重试。若余款都被冻结，余额
  仍可能拒绝新通话，这与错误的并发锁定是不同问题。
- 已修复：建立时长 alarm 失败时，若释放 Credit 再失败，原代码不会关闭已连接的两个 socket。
  现在先关闭两端，再做额度清理。没有改变通话成功时的价格、时长或设备权限。
- 已加入 Voice 账务补偿底座：持久化预留前意图、通话 checkpoint 与结算/释放任务；只有 RPC
  返回期望终态才删除，异常由 alarm 重试。Auth 仍在余额计算中忽略超过两小时的 pending 预留，
  此机制不等于对账；运营队列界面与存量异常账务核对仍待建设。
- 已加入 Voice 实例恢复：重建后按持久化 checkpoint 计费，不将停机时间算给用户；正常挂断
  保存实际时长。WebSocket 生命周期与 alarm/storage 故障边界有回归测试，真实 DO 仍需端到端验收。
- 已加入服务间结算身份：新的私有 `finalizeVoiceReservation` RPC 绑定账户及既有 Voice
  reservation，不依赖 25 分钟浏览器票据；入口覆盖 subject，不接受客户端指定账户。
- 已加入 Voice 结算结果检查：`settled` / `released` 之外的结果保留待重试任务。文字 LLM Worker
  也校验结算终态及实扣值，同一结算/释放动作至多重试 3 次，不在结算不确定后改为释放。
- 流式文字取消会传递给上游 reader；终止前收到有效 usage 时结算已确认用量，没有有效 usage 时
  释放，不从文本长度推算扣费。`[DONE]` 结束上游读取，忽略其后的事件，避免等待不关闭的连接
  而一直不结算。客户端仅在结算确认后收到 `[DONE]`。
- 文字预留 RPC 超时、异常或非法状态会阻止模型启动，并返回 `billing_status: unknown`。
  不确定预留不自动释放，因为请求可能已提交；重复 pending key 不重新生成。此处不提供恢复
  响应正文的能力。文字新增 0039 持久 outbox 和 reservation capability，确认用量可由 Auth 分钟 cron 幂等补偿；
  未确认用量或已过两小时冻结有效期的任务进入 needs_review，不猜扣费。
  上述修复均未更改现有模型价格，未修改 Auth、Voice 或设备路径。

## 验收分界

单元回归覆盖网络失败、未升级 WebSocket、alarm 失败叠加额度服务失败：本地并发锁恢复、已打开
socket 关闭，且不伪称账务释放成功。真实 provider、浏览器/Android 连续通话、断线恢复与设备
停止仍需专门端到端验收，本次未进行硬件测试或生产调用。

后续统一会话验收必须包含：文字转语音后仍记得同一人物和上下文；通话完成后另一设备能看到
字幕；相同消费不会重复扣款；群聊不会看到私人记忆；所有入口的余额一致；Voice/摄像头退出后
原有设备停止路径仍有效。未来允许服务器存储的聊天字幕与附件，不包括当前承诺不存储的原始
摄像头帧或未经用户选择保存的音频。

## 文字持久账务补偿（0039，尚未部署）

Auth 私有 RPC 注册任务后代理才启动模型。每个有效 usage checkpoint 先持久化再交付对应帧；
终结意图独立落库，账本、预留与任务终态随后同事务写入，事务失败仍可恢复。随机 capability
仅绑定该 reservation，不允许指定其他账户，也不依赖过期浏览器凭据；不存储对话正文。
分钟 cron 限 20 项并持久退避，10 分钟无心跳/用量更新的停滞任务按已有确认用量结算。无用量或过期预留留
needs_review 并释放，现阶段需运营查询 D1，不能声称自动查到 provider 未返回的使用量。
早期流式正文仍可早于最终 usage 显示。上线顺序必须是 0039 → Auth → LLM proxy，旧代理仍可
使用旧 RPC；新代理不会在缺少持久接口时降级。无需新增云资源，本次无部署及生产付费调用。

运行期间代理每分钟持久化心跳，心跳 RPC 3 秒内未确认则中止后续转发与交付；未知用量保留
任务待核对，不宣称释放成功。心跳不刷新原预留的2小时TTL，过期会拒绝续约。

## 文字账务运营可见性（0040，尚未部署）

原管理对账面板已接入 pending / needs_review / 已有备注任务的分页视图，显示确认token、
预留/实扣/任务状态与原因，不暴露内部capability或对话。管理员可添加带观察状态的不可变
核对备注，重复提交幂等，状态改变返回冲突；未封禁管理员身份和账号固定头均需验证。
备注保留审计证据，不修改账本、不标记异常为修复；确认用量仍交0039恢复，未知用量/过期
预留没有安全证据支持人工强制扣费，因此本轮没有开放此类财务操作。后台恢复后已有备注
继续可见。此界面尚不能替代provider账单取证或自动下载对账，仍需后续真实上游账单适配。

## 单一账户消费视图（未部署）

设置账本通过 timeline 查询将同一reservation与usage账本合并，保留释放、过期及待核对记录，
并保留充值/奖励等原账本。媒体任务提供真实job/conversation/relationship关联；Voice与文字
当前没有会话字段，明确未知。主动生成仅能确认schedule关联，未用计划现值冒充历史归属。
展示真实保留的价格版本，不补造历史价格；异常仅安全状态说明，不公开provider错误或凭据。
没有新增余额、没有账本迁移、没有收费策略变化；跨入口写入会话身份仍需后续执行链改造。

## 新文字与Voice消费归属（0043，未部署）

已补实际预留入口的conversation/run快照。私人Agent从正在执行的session传递会话、以每次
模型请求幂等ID标记run；Voice从本次已准备的服务器channel传递会话，以字幕共用callId标记run。
Auth核验owner与未删除会话，再记录预留时关系快照；重复请求不改归属，公开试聊/房间不推断
私人关联。旧记录仍unknown，余额、Token/时长价格、设备权限没有变化。上下文写失败不启动
provider并尝试释放新hold；账户数据服务不可用时不能保证立即清理，沿用TTL与异常日志。

## Voice 迟到结算封口（0044，未部署）

真实 SQLite 回归复现余额 100、Voice 冻结 80 过期、其它消费 80 后迟到结算再扣 80
的问题。现以写账时 TTL 条件阻止过期扣费，原子保存过期审计并释放；余额保持 20。
重复、并发、审计事务回滚以及应用时间落后数据库时间均有回归。Voice durable outbox
确认 needs_review 且无扣费后停止重试，避免无限补偿。统一消费流水只读显示过期原因与
未扣费，账户隔离保留。Voice 已新增0045管理员只读队列及不可变备注，运营 D1 查询路径仍见 Auth README
“Voice 过期冻结审计”；不能据时长报价猜测追扣。正常计费价格、设备执行边界不变。

Voice 管理审核（0045，未部署）补齐账户/时间筛选与同毫秒分页；备注事件幂等并绑定观察状态，
管理员不能借备注修改账本或强制结算。UI 展示请求报价为证据，不把它称为实际扣费。文字审核
和订单退款面板保留。数据库鉴权、错误账户、重复事件、分页与UI重试/筛选竞态有本地回归。
