# 6.5 Credit 模型服务计划

## 新版定位

`6.5.0` 直接将 **0xNullAI 模型服务**设为 Agent 的默认正式版本。旧“免费体验”不再作为一个
provider 存在，也不做长期双轨。用户登录后使用 Credit；余额不足时充值、通过邀请获得 Credit，或
切换到自己的 API。

基础兑换比例先定为 **1 美元 = 1000 Credit**。人民币人工充值采用固定产品价
**7 元 = 1000 Credit**，不跟随每日汇率浮动；成功邀请奖励 **500 Credit**。

自己的 API 继续保留现有官方、第三方和自定义兼容能力，不消耗 Credit。旧 BYOK 配置继续可用，
避免升级后要求用户重新填写 Key。

## 简化后的 UI

Agent 默认只显示一个模型选择器：

- 顶部显示当前平台模型。
- 用户名旁显示 Credit 余额。
- 模型列表显示“基础、均衡、强力”三个档位和预计 Credit，不展示底层模型、网关和协议。
- 余额不足时在输入区附近显示“Credit 不足”和“充值”按钮，不清空已输入内容。
- 未登录时把发送按钮替换为明确的“登录后使用”。

模型选择器底部保留一个低强调入口 **“使用自己的 API”**，不再用两张大卡片让用户先选择模式。
进入后默认只显示服务商、API Key 和模型。

Base URL、接口协议、Strict Schema、网络代理和连接测试收进同一个“高级设置”。普通预置服务商使用
默认值；选择“自定义”时才自动展开必要字段。代理字段只说明“启用后，模型请求将通过该地址发送”，
不增加额外模式或确认弹窗。

设置页提供“切换回 0xNullAI 模型”。Agent、Chat 和 Video 共享模型来源；Video 只展示明确支持视觉
输入的模型。Voice 保持独立模型设置和通话页面，但在 6.5.0 一并接入同一个 Credit 余额。

账户页保留余额、充值、用量记录和邀请记录。小屏中 Credit 只出现在用户名旁，邀请卡片只显示
“邀请好友，获得 500 Credit”、链接和分享按钮，详细记录进入二级页面。

## 交友与个人主页

交友从侧栏弹窗改为完整页面，使用 `/people` 承载好友、关注、粉丝、发现和黑名单；个人主页使用可
分享的 `/u/:username` 路由。桌面可在主内容区浏览，手机使用全屏页面和返回导航，不在窄屏上叠加
多层弹窗。头像、用户名或聊天成员卡都进入同一个主页。

关系仍采用清楚的单向关注模型：双方互相关注后显示为“好友”并允许私聊；取消关注立即关闭当前私聊
连接但保留历史，再次互关后恢复入口。用户可以移除粉丝，拉黑会删除双方关注、结束实时私聊并让双方
在搜索、发现和列表中彼此不可见；解除拉黑不会自动恢复关系。

`/people` 包含：

- 好友、关注、粉丝三个列表，显示头像、昵称、用户名、关系状态和可用操作。
- 精确用户名搜索，以及只展示主动选择“允许被发现”的公开资料的发现页。
- 发现筛选仅使用用户主动填写的兴趣标签和城市级地区；不使用精确位置、通讯录上传或隐式行为画像。
- 推荐结果分页、限流并适度随机化，不提供全站用户目录、总用户数或批量导出接口。
- 好友可直接发起私聊、查看主页，或邀请进入现有房间；房间邀请是可撤销的站内邀请，不自动把用户
  加入房间，也不向非好友开放批量邀请。
- 每个列表都有加载、空、断网、失败重试和操作中的明确状态；手机行内只保留一个主操作，其余进入
  更多菜单。

个人主页首屏展示头像、昵称、`@username`、一句简介、兴趣标签、城市级地区、关系状态与主要操作；
下方展示用户主动公开的相册和站外链接。生日只用于服务端成年校验，具体日期永不公开；不显示精确
位置、最近在线时间、设备、Credit 余额、消费、邮箱、手机或邀请收益。

资料可见性扩展为“公开 / 仅好友 / 仅自己”，并允许相册照片单独设为公开或仅好友。旧的公开与私密
设置迁移到对应新值，不扩大任何旧资料的可见范围。用户可以关闭被发现，但仍可通过准确用户名和已
存在的聊天关系访问其允许查看的资料。

主页编辑使用实时预览与固定保存栏，字段均为选填；头像和相册上传限制格式、尺寸和数量，服务端移除
图片元数据，私密资源不能依靠可猜测的永久 URL 绕过权限。举报入口覆盖冒充、骚扰、不当内容、垃圾
信息和其他原因；后台保留处理状态和审计记录，但不把举报结果泄露给被举报人。

## 我们自己的接口

- `GET https://llm.0xnullai.com/v1/models`：返回平台允许使用的模型和能力。
- `POST https://llm.0xnullai.com/v1/chat/completions`：生成入口，兼容现有 Agent/Video 客户端，使用 SSE 返回文本、工具调用、用量和
  本次 Credit 消耗。
- `GET /api/credits/balance`：账户的可用与预留 Credit。
- `GET /api/credits/ledger`：充值、邀请奖励、消费和退款记录。
- `POST /api/admin/credits/grant`：管理员确认到账后人工增加 Credit。

## 充值方案

`6.5.0` 只使用后台人工确认入账，不接入 Stripe、支付宝商户接口、应用内购买或自动充值。支付渠道
以后另立项目评估，不属于当前版本计划。

### 6.5.0 人工充值

人工充值仅用于受控内测。用户在应用外把支付宝口令红包交给管理员；管理员领取并确认实际到账后，
在受 Cloudflare Access 保护的后台选择用户、固定充值档位和外部流水备注，系统写入一笔
`manual_purchase` 账本记录。人民币首发档位如下，不设置折扣或赠送：

| 人民币 | Credit |
| -----: | -----: |
|   7 元 |  1,000 |
|  35 元 |  5,000 |
|  70 元 | 10,000 |
| 140 元 | 20,000 |

后台不能手填换算率或最终 Credit，服务端根据版本化价格表计算。账本保存原始人民币金额、价格版本和
最终 Credit；以后调整价格只产生新版本，不修改历史记录。非标准金额默认不入账，避免人工换算误差。

产品和服务器不收集、保存或自动领取红包口令，也不把口令红包宣传成正式支付方式。管理操作使用
`POST /api/admin/credits/grant`，必须带管理员身份、原因、外部引用和幂等键；外部引用只能入账一次。
错误操作通过负向调整冲正，不能修改或删除原记录。账户侧只显示“人工充值”、Credit 数量和时间。

人工充值设单笔与每日上限，并保留管理员审计记录。它同时可用于客服补偿和账务修正，但这些原因使用
独立的账本类型。没有管理员确认实际到账时不得增加 Credit。

生成请求通过登录 Cookie 或 Bearer 会话鉴权，并携带 `Idempotency-Key`。Worker 验证模型白名单，
预留额度，通过同账号的 Cloudflare Workers AI binding 调用模型，再按实际用量结算，不需要第三方
模型 API Key。失败、取消或模型不可用时释放预留。

## Agent、Video 与 Voice 计价

所有平台模型在调用前预留 Credit，成功后结算，失败或取消释放预留；使用自己的 API 时三者都不扣
Credit。客户端显示预计消耗，价格和最终用量只能由服务端决定。首发统一使用
`ceil(上游实际成本（美元） × 1500)`，单次成功调用最低 1 Credit；价格版本保存在每笔账单中。

### Agent

按模型实际输入、缓存输入和输出 Token 分别计价，服务端模型目录返回每百万 Token 对应的 Credit。
工具调用产生的后续模型轮次分别计费，但同一个幂等请求不能重复扣款。界面只显示“约消耗 N Credit”
和本次最终消费，详细 Token 数据放在用量记录中。

### Video

当前 Video 是摄像头截图的视觉分析，不是视频生成。摄像头可以每秒刷新本地预览，但只有送入模型并
成功完成的分析帧收费。界面根据模型、图片尺寸、提示词和预期输出显示每帧及每分钟估算；服务端按
上游返回的实际视觉输入、文本输入和输出用量结算，不把 5/10 Credit 的估算写成固定价格。失败帧和
被新画面替换而取消的请求不收费。

默认分析间隔为 10 秒，允许的最短间隔仍为 5 秒，界面在用户修改间隔时同步更新预计每分钟消耗。
开始前预留下一帧的估算费用；余额不足时停止新的分析并立即停止由 Video AI 控制的设备，不影响纯
本地摄像头预览。

### Voice

平台 Voice 首发使用当前实时语音 Worker，但升级到受支持的 xAI `grok-voice-think-fast-2.0`。官方基础
价格当前为每分钟 0.08 美元，平台暂定 **每 10 秒 20 Credit**，即最多 120 Credit/分钟。连接失败不
收费；成功连接后按实际连接时长向上取整到 10 秒，单次最低 20 Credit。

建立连接前按账户余额和单次时长上限预留本次通话可能使用的 Credit，结束后释放未使用部分。余额不足
20 Credit 时不建立连接；达到余额对应时长或单次上限时由 Durable Object alarm 结束通话。结算使用
Durable Object 记录的实际连接时长，异常断线仍按已连接时间结算。

## 与 Agent 的对应

Agent Core 继续只依赖 `LlmClient.runTurn()`，不感知 Cloudflare、Credit 或供应商：

```text
Agent Runtime
  -> LlmClient.runTurn()
     -> OpenAiHttpLlmClient     -> llm.0xnullai.com/v1/chat/completions（平台托管）
     -> OpenAiHttpLlmClient     -> 用户选择的 OpenAI 兼容 API
     -> PiAiLlmClient           -> Anthropic、Google 及现有第三方 API
  -> LlmTurnResult
  -> 工具权限与设备安全执行
```

组合层只根据当前来源创建对应客户端。三类客户端把流式文本、推理内容和工具调用转换为同一个
`LlmTurnResult`，因此 Agent 的会话、工具、权限、多设备路由和紧急停止逻辑不需要分叉。

## Credit 与数据

Credit 使用追加式账本，记录购买、邀请奖励、预留、消费、退款和人工调整。每个模型的换算价格在
服务端维护版本；每笔消费保存输入、输出等计费用量和价格版本，客户端不能提交价格。

现有邀请实现中的 `reward_cents`、`balanceCents` 改为 `reward_credits`、`balanceCredits`。迁移时把
现有数值按 Credit 原值转换，并保持邀请奖励为 500 Credit。用户 Credit 与 Cloudflare 预付余额分别
记账，后台监控两者差额。

自己的 API Key 只保存在当前设备。网页默认按会话保存，用户主动选择后才持久化；桌面和 Android
使用系统安全存储。Key 不进入账户同步、0xNullAI Worker、遥测或日志。

## 保留与清理

保留：

- OpenAI、Anthropic、Google、Qwen、DeepSeek、豆包和目前可用的第三方 provider。
- 自定义 Base URL、Responses/Chat Completions、Strict Schema、代理和模型发现。
- 现有 OpenAI 兼容与 pi-ai 协议客户端。
- 能验证成功的旧 BYOK 数据和设置。

清理：

- `free` provider、`openrouter/free` 展示模型和每日体验额度。
- 免费代理专用 HMAC、cookie 分支、APK 内共享 secret 和相关环境变量。
- 失效或没有真实调用路径的 provider 定义。
- 重复的 provider 判断、连接测试、设置状态和兼容测试夹具。

## 实施顺序

1. **价格与模型**：确定首发模型、每个模型的 Credit 换算和人工充值换算规则。
2. **账本与内测入账**：完成预留/结算、邀请入账、用量查询和受审计的人工 Credit 管理。
3. **ManagedLlmClient**：实现 `/v1/models`、`/v1/responses`、SSE、工具调用和余额错误。
4. **默认 UI**：平台模型成为默认，接入余额、登录、充值和“使用自己的 API”次级入口。
5. **BYOK 整理**：保留能力，压缩默认字段，高级配置折叠，验证旧设置迁移。
6. **Video 计费**：按成功分析帧预留和结算，并在分析间隔旁显示预计每分钟消耗。
7. **Voice 计费**：实时连接按 10 秒分段预留和结算，余额耗尽时安全结束通话和设备控制。
8. **交友与主页**：把弹窗迁移为路由页面，完成发现开关、兴趣标签、好友房间邀请、三级可见性和
   图片访问保护，同时迁移旧资料而不扩大可见范围。
9. **模块验收**：Agent、Chat、Video、Voice、账户、邀请、交友、主页、侧栏和多设备在桌面及窄屏
   逐状态检查。
10. **移除免费链路**：发布候选版前删除文本和语音免费体验的代码、配置、模型、额度、文案和密钥；
    生产检查确认旧免费端点不可再调用，6.5.0 不保留双轨或免费回退。
11. **发布 6.5.0**：网页先灰度，再发布 Android、Windows 和 Apple Silicon macOS；人工充值仅向内测
    用户开放。

## 发布门槛

- 并发、断线重连和重试不能重复扣款，失败请求全部释放预留。
- 客户端不能绕过模型白名单、修改价格或伪造上游用量。
- 人工入账具备管理员鉴权、幂等、上限和不可删除的审计记录。
- Agent 工具和设备继续在最终执行边界验证身份、连接、权限与安全限制。
- 拉黑立即撤销关系和实时私聊；资料可见性、相册权限与发现开关均由服务端执行，客户端隐藏不能作为
  权限控制。
- BYOK 旧配置升级后仍可使用，API Key 不进入服务端或日志。
- 网页、Android、Windows 和 Apple Silicon macOS 完成登录、余额、平台模型、BYOK、流式输出、
  视觉计费、实时语音计费、断网和多设备验收。
- Cloudflare 日志、费用告警、账户/IP 限流、全局预算上限和紧急停用开关上线后才能开放模型服务。
- 免费 provider、免费模型目录、免费额度和旧代理认证全部移除，旧免费端点返回明确的停用响应且不能
  产生上游调用；此项未完成不得发布 6.5.0。
