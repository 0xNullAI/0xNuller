# 网站统一聊天与角色平台：执行计划

状态：2026-09-29 确定的产品与工程边界。此文档是实施依据；[早期调研与过程记录](companion-platform-plan.md)中关于内置场景、多人场景、多角色 AI 编排及旧导航的设想，以本计划为准。当前代码仅在 `develop` 分批开发，本文的“目标”不表示已上线。

实施方式：先核对现有结构与新需求的差距，优先修复原有页面、服务和共享接口；只有现有边界无法承载会话、权限或计费语义时才拆分或重写。视觉改动逐页评审，不为“全面升级”把已能工作的 UI 整套替换。

## 一、最终产品形态

网站先进入**统一登录页**；登录后以**消息**为首页。直接打开旧链接或分享链接时保留目标地址，登录后回到该页面，各功能页不再各做一套登录入口。AI 私聊、真人私聊和真人群聊使用同一会话列表、消息样式、搜索、未读、附件与发送状态。AI 是消息参与者，不再需要用户在不同“对话类型”或左上角模式间切换。手机端参考 QQ 的会话与联系人组织方式；宽屏采用简洁的侧栏、会话列表和聊天区，个人设置在侧边或独立页面展开。设置采用列表与二级页面，不使用堆叠下拉栏目或账号弹窗。页面控制文字密度和字号层级，设备页不重复显示“我的设备”“连接”等无实际信息的标题。

一级去向是消息、联系人/群、发现、设备和我的。原 Agent、Voice、Video、Chat、Control、Market 的有效入口及旧链接仍可到达，逐步变为同一聊天上下文中的能力入口；原管理界面保留。设备是重要产品能力，现有连接、协议、权限、上限与紧急停止链路不重写。未登录/已登录、未连接/已连接、手机/平板/宽屏都需要真实空态和可操作页面。

真人个人主页在登录后可公开浏览，不提供匿名访问或整页私密/仅好友模式；个人主页的展示资料、作品和已明确公开的相册可被其他登录用户查看。既有私密照片、聊天、关系记忆、设备状态及被屏蔽用户的数据不能因主页改公开而自动披露。公开作品与主页内容的联动按独立授权和审核实现。

所有新聊天记录、附件索引、生成结果、任务状态和账务由服务器作为权威来源。浏览器只保存当前页面内存中的显示状态与未提交输入，不把新聊天历史写入本地数据库、localStorage 或缓存。旧本地历史须在用户确认归属后可恢复、可校验地迁移；未成功回读前不能删除源数据。

云端主存储与独立备份分开验收：AI 会话原文在账户 D1，真人私聊/群记录在 Chat Durable Object，图片和语音对象在 R2；这些在线副本使跨端恢复成为可能，但不自动构成一份可独立验证的长期备份。发布前需确认生产 D1/SQLite Durable Object 的时间点恢复能力与实际保留期，并为会话及媒体建立独立、加密、版本化的定期导出；备份记录覆盖账户/会话 ID、范围、时间、消息数、媒体清单与校验和。恢复演练必须在隔离环境回读 AI、私聊、群和附件，核对缺口与顺序；删除账号、撤回或到期清理也必须作用于备份或其解密密钥，不能让已删除记忆从旧备份回流。真人群现有最近消息保留上限不等于完整历史备份；若产品承诺长期可回看，必须先增加归档与分页读取，再按新保留规则清理。

## 二、卡片、实体和 Market

公开内容只有三类：**角色卡、场景卡、波形**。角色与场景共用 Market 的 `scenario` 存储、发布、版本和审核，但以不可变的 `content.kind` 区分；波形继续走原设备内容模型。

| 对象         | 保存与归属                                                            | 使用结果                                                                                              |
| ------------ | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 公开角色卡   | 作者发布的名字、基础人设 Prompt、头像、简介、可选开场/示例/标签与版本 | 用户导入后生成自己的角色实体，可聊天、命名、建立关系与记忆                                            |
| 公开场景卡   | 作者发布的环境、故事背景、规则 Prompt、展示资料与版本                 | 用户导入后生成自己的场景实体，可应用到聊天；自身没有关系、主动消息或记忆                              |
| 个人角色实体 | 当前账户 + 稳定公开卡 ID 对应的私有实体 ID                            | 保存我的 AI 名字、私人头像、AI 对我的称呼、音色、关系、安全选择和记忆；同一公开卡在不同账户下完全隔离 |
| 个人场景实体 | 当前账户 + 稳定场景卡 ID 对应的私有实体 ID                            | 保存采用的卡片版本、用户自己的场景参数；不创建角色关系或长期记忆                                      |
| 会话         | 服务器 conversation ID、参与者和可选 `characterId`/`sceneId`          | 一个角色可以应用一个可选场景；换场景不替换角色的身份和记忆                                            |

**不再提供代码内置场景、内置角色卡、内置模式、原创起点，也不再支持 Market 多人场景或多角色 AI 编排。** 角色和场景从 Market 浏览、作者创建或导入外部卡，经个人导入后实体化。通用 Agent 工具属于平台能力，不伪装成一张内置角色卡。现有用户自建卡与旧会话保留，不能因移除预置入口而丢失。历史 prompt-only 内容按场景读取，结构化人物卡按角色读取；不自动把旧场景改成有记忆的角色。

卡片分**公开版本、个人实体、会话绑定**三层。公开角色卡以名称、基础人设 Prompt 为必填，头像、简介、开场、示例对话和标签为可选；公开场景卡以名称、环境/规则 Prompt 为必填，可附背景、开场和标签，但不能写入人物关系、私人记忆或设备授权。导入时保存公开版本的私人快照；作者发布新版本只提示用户选择更新，不悄悄覆盖个人改名、头像、关系或已有聊天。会话只引用一个私人角色和可选场景；切换场景只影响后续叙事，不改变角色身份或其长期记忆。作者编辑器先给名称、Prompt、预览，再按需展开资料、素材、版本说明与发布权限；导入外部卡需显示解析结果和许可信息，由用户确认后成为私有草稿。

每轮模型上下文按固定优先级组装：平台与设备安全规则 → 已导入的角色快照 → 当前场景快照 → 此账号/角色/会话获授权的关系记忆 → 有来源的中期摘要与相关旧消息 → 最近完整消息轮次 → 本轮输入。角色卡或场景 Prompt 永远不能升级为设备权限；摘要不代替服务器原始聊天。超出模型预算时先减少相关旧消息，再压缩中期摘要，始终保留当前轮、必要的近期上下文与设备安全规则，不截断半个工具调用。记忆事实的引用、纠错、删除和作用域规则见下节。

Market 发现页上排固定为“浏览全部／我的收藏／关注作者”，下排为“角色／场景／波形”，**创建**在下排最右。排序与类型放入简洁的筛选面板。角色详情可以导入并开始聊天；场景详情只能导入或应用于已有聊天，不单独开始一段角色关系。在线编辑器首屏仅名称、基础 Prompt 和可选头像；详细字段按需展开，支持私有在线草稿、冲突检测、发布版本、外部卡片导入和手绘头像。公开卡与个人实体设置分开，防止私人称呼、记忆或头像误发布。精选内容只使用原创或许可清晰的卡片；不得未经许可预置第三方内容。

## 三、记忆、关系与安全

消息原文形成短期上下文；跨会话摘要形成中期记忆；稳定事实、人物和事件形成长期记忆；称呼、共同约定、重要日期及互动历程形成关系历史。每条可长期使用的记忆保存来源、作用域、版本、确认状态和删除/替代状态。模型推测、虚构剧情和生成图片不能自动变成现实中的用户事实。同名人物先消歧，不自动合并。

“我的”设置管理账号级记忆与默认安全设置；每个 AI 私聊、真人私聊或群聊的二级设置可选择该聊天能使用或共享哪些资料。默认不把一个 AI 的私密记忆给另一 AI、真人或群。真人资料、朋友圈中的人物与事件只来自用户主动输入或明确授权分享；不默认抓取外部社交平台。角色的个人设置可改名字、称呼、头像、关系方式、主动消息、语音与已确认记忆。用户可查看来源、纠正、删除、暂停、导出记忆；删除须同步到摘要、检索索引和缓存，不能下次从旧消息再次“记回来”。

先使用已有服务端事实表和检索能力作为基线。把 Mem0 作为**可替换的抽取/检索候选**，用相同匿名中文对话评测跨会话回忆、姓名消歧、纠错、遗忘、作用域隔离、延迟和每千轮成本。无论选哪种实现，账户、权限、原始消息、事实来源和删除权威仍在本项目服务器；不把外部记忆服务变成唯一副本。[Mem0 官方 API](https://github.com/mem0ai/mem0/blob/main/skills/mem0/references/api-reference.md)提供按用户等标识检索和更新/删除操作，但这些接口本身不解决本产品的授权边界。

长对话采用“原文在用户删除或保留期到期前完整在线保存，模型上下文按预算重建”：短期取最近完整轮次，中期维护带来源消息 ID 与覆盖范围的滚动摘要，长期取已确认且与当前话题相关的事实及关系事件。摘要写入前核对账户、角色、会话作用域，用户纠错/删除后使受影响摘要失效并重建；摘要不能自动生成新的事实。检索同时考虑关键词、语义、人物消歧和时间，设置总 token 预算及各层上限，不把十万条原文直接送给模型。Mem0 官方资料显示其新开源版本采用[ADD-only 抽取和混合检索](https://github.com/mem0ai/mem0/blob/main/docs/migration/oss-v2-to-v3.mdx)，所以纠错与删除必须由本产品明确驱动，不能假设接上 SDK 就会自动处理；[Letta 常驻 memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks)适合参考小容量人设/偏好块，[Graphiti 的时序事实与来源](https://help.getzep.com/v2/graphiti/getting-started/overview)可作为人物关系复杂时的评测候选，均不取代现有服务器权威存储。

主动聊天分用户指定时间、事件跟进和可选柔性问候。按角色单独开启，包含时区、安静时段、频率上限、未回复退避、预算、取消和通知设置。服务端到期前和发送前都重验权限与新消息，幂等写入同一会话，网页关闭仍可执行。主动消息永远不触发物理设备操作。Nomi 的[主动消息](https://nomi.ai/nomi-knowledge/proactive-messaging-when-your-nomi-messages-you-first/)和[情境自拍](https://nomi.ai/nomi-knowledge/getting-started-nomi-selfies/)可作为体验参考；具体节奏与质量须以本项目测试决定。

安卓版不做系统推送（2026-10-11 产品决定）：用户多在国内，多数手机没有 FCM 需要的 Google 服务，FCM 代码已移除。AI 主动消息、真人私聊和群聊的新消息先保存到服务器，再以站内未读（导航角标、标题计数，网页可选浏览器通知）呈现。若以后接推送，优先评估国内厂商通道或聚合服务。

账号默认安全策略与聊天级开放使用同一套权限语言，不按 AI/真人拆两套设置。角色卡、场景 Prompt、群消息及模型输出都不能授予工具或设备权限；设备最终执行仍以当前设备身份、连接、许可、租约和安全限额为准，停止操作始终可达。

## 四、统一消息、真人社群与 Agent

服务端提供稳定会话、参与者、消息、附件、任务和未读游标契约。前端可聚合现有 AI、真人私聊与 Chat 房间，而不必一次把所有后端搬到同一张表；对用户表现为一个收件箱。发送使用幂等 ID，服务端序号排序；重连按游标恢复，双端同时发送不互相覆盖。消息可显示发送中、已接收、生成中、失败和已完成。长期真人群有独立成员、权限、历史和未读；现有临时房间保留原生命周期。**保留真人群聊，删除多人场景与多角色 AI。** 若群中需要 AI，只允许明确加入的单个 AI 由用户 @ 触发，并由触发者授权和付费；不做多个 AI 自发互聊。

Agent 工具以郊狼等设备控制为重点，Memory 则是陪伴产品的核心上下文服务，不因工具收拢而删减。文件读取、任务和提醒是可选的授权工具，按真实使用场景逐项加入，不作为首批设备执行链的依赖。区别是：记忆提供有来源、可纠错的长期知识；工具发起一次有权限和结果状态的操作；角色/场景只配置叙事，不能授予任何操作权限。设备调用使用可恢复的 `TaskRun`：调用 ID、真实结果、失败/拒绝、预算和状态均由运行时记录。模型只能请求获授权的工具，不能自己宣称执行成功；最终回复涉及设备操作完成态，必须对应可核验的结果。对模型“假装调用工具”设置输出校验与回退说明；设备任务允许有界循环、取消和超时。群内设备工具不能继承其他成员凭据，只在当前已连接、授权的本机执行。

执行契约具体为 `runId` 贯穿会话消息、模型轮次、每个 `callId`、工具结果和费用。运行状态按“待执行→运行中→等待工具/用户→已完成/失败/取消/待核对”持久化；每个设备调用先校验 schema、账户与聊天权限、设备授权、步骤数/时限/费用预算，再以幂等键执行。成功、拒绝和失败都生成可追踪的结果收据；模型下一轮只读真实收据。消息 UI 从设备收据呈现执行状态，不靠模型自由文本判断是否发生；最终回复若声称完成但无对应收据，改为明确的未完成状态并提供核对方式。设备工具须在本机最终执行边界核验权限，不能把返回一段 JSON 视为设备动作成功。多个窗口重试同一 `runId` 不启动第二次工具或第二次扣费。

现有 runtime 已有有界工具循环和对可识别虚假完成语句的校验，但它基于回答措辞与当轮结果，尚不是服务端持久 `TaskRun`，也不能证明所有语言、工具与跨窗口故障都被覆盖。这一层保留为过渡保护，正式完成门槛是结构化工具收据、服务端恢复与缺失/拒绝/超时/伪造结果的端到端测试。

事实性回答另用已授权的角色记忆和会话来源、不确定性表达约束；无法查证时明确说不确定。评测集分别测“假装执行设备工具”和“编造事实”，不把前者的拦截率冒充所有幻觉都已解决。

## 五、语音、视频、头像与 Credit

文字、语音、图片、视频和工具任务属于同一会话时间线。语音从聊天进入，沿同一角色实体、可选场景和授权记忆运行；通话结束把可见记录或摘要写回服务器，失败不能留下虚假的已完成消息。Video 区分摄像头理解与生成短视频；先接好已有摄像头能力与消息，再加情境图片、短视频。Avatar/AR 暂不进入当前实施批次，保留为后续独立评估的扩展。公开头像与仅个人可见的手绘/上传头像分开；情境自拍使用角色外观、当前场景及最近对话，但生成结果不自动进入公开 Market。

所有托管模型、实时语音、生成图片/视频和 Agent 工具使用**同一个 Credit 预留→执行→按真实用量结算/失败释放→账本**契约。必要时以统一 API 代理收束目前分散的服务商调用；BYOK 保留为明确的高级路径，不绕开服务器聊天与权限契约。支付闭环包含可见充值入口、订单、回调幂等、到账、消费明细、退款和对账；生成任务在聊天里显示预估与最终费用。创作者奖励仅发可用于 AI 消费的 Credit，**没有提现**。MiniMax 等服务商以质量、延迟、价格、可用性和协议适配实测选择，不锁定单家。

计费接口对各模态统一 `quote → reserve → execute/checkpoint → settle 或 release → reconcile`，每笔保存 `accountId`、`conversationId`、`runId`、`modality`、`provider/model`、价格版本、预留额、可信实际用量及终态。模型 Token、语音连接时长、视觉帧和媒体任务各有计量适配器，但使用同一幂等键规则和账户账本；一条会话可展示其文字、语音、媒体和工具费用。预留不明确时不启动服务商；结算是否提交不明确时进入待核对，不猜测扣费或反向释放。图片/视频须在结果对象成功保存后才结算交付，失败按既定规则释放或核对。管理员保留只读异常队列与带审计的备注；真实上游账单对账和退款另行验收。

目前文字代理、Voice 与部分媒体任务都接触现有 `credit_reservations`/`credit_ledger`，已有若干失败补偿和管理查看代码，但协议入口、会话归属、价格展示及运营对账尚未完全合一；部分迁移和代码只在本地 `develop`，未做生产付费端到端验收。统一 API 代理是可选的外层路由和价格目录，不强迫实时 Voice、流式文字与异步媒体共用一种传输协议，也不另建钱包。

## 六、执行批次与验收门槛

批次是依赖顺序，**不是删减功能**。各批可由 UI、后端、Agent/媒体并行开发，但共享契约、迁移和安全验收必须先稳定。

三条工作线并行推进，避免 UI、后端和模型各自定义一种“聊天”：

| 工作线       | 主要工作                                                                                       | 先决接口与交接物                                                       |
| ------------ | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| UI / 体验    | 首页和统一会话、联系人/群、设备连接态、设置二级页、Market 与编辑器、宽窄屏和低文字密度         | 共用会话/卡片/权限状态定义；用真实未登录、登录、未连接、已连接状态验收 |
| 后端 / 数据  | Market 类型与迁移、个人实体、服务器消息、附件/任务、记忆来源与作用域、主动调度、群、订单和账本 | 稳定 ID、幂等写入、游标和版本契约；先完成兼容迁移再切新写入            |
| Agent / 媒体 | 角色加场景 Prompt 组合、工具结果 trace 与多步运行、记忆检索、Voice/Video 统一、服务商代理      | 只读取后端授权快照；工具与媒体结果回写同一会话和费用账本               |

第 0 批先合并接口契约和迁移策略；随后 UI 可并行做布局与状态、后端实现数据 owner、Agent 复用同一 ID。每批合并前走一条从 Market 导入到聊天、跨端恢复、工具/媒体返回消息及结算的端到端路径，不以各模块单独“看起来可用”代替集成验收。

| 批次                | 交付                                                                                                                                                    | 完成门槛                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 0. 清理与契约       | 移除内置场景/角色预置和多人场景入口；Market 角色/场景 `kind`；确认个人实体、会话参与者、消息、费用与权限契约；梳理旧记录迁移                            | 旧自建卡和会话可打开；角色/场景不能误转型；真人群、设备连接和紧急停止不退化             |
| 1. 消息与发现       | QQ 式手机会话、简洁宽屏收件箱、联系人/群/设备页、设置二级页；Market 分类、筛选、创建/编辑/导入；服务器权威消息、跨端续聊与旧历史迁移；私有角色命名/头像 | 登录/未登录、连接/未连接和 320px 至宽屏均可用；双端并发无丢消息；新聊天不落本地持久存储 |
| 2. 持续关系与 Agent | 短中长期记忆、人物事件、关系历史、账号/聊天级安全开放；定时和主动消息；工具结果证据、有界多步任务；真人常驻群和单 AI @                                  | 纠错/删除不复活，跨角色/群零越权；取消后不主动触达；无真实结果不宣称工具已完成          |
| 3. 多模态与支付     | 文字与语音连续、已有摄像头入口统一；情境图片、视频任务和相册；统一 Credit 代理/预留结算；正式充值、退款、对账；作者 Credit 激励                         | 通话和媒体回同一时间线；失败释放预留、重试不重复扣费；订单/账本可对上                   |
| 4. 社区与扩展       | 作者关注、内容收藏与规则推荐、公开社群发现；更多授权工具与媒体质量迭代；长期关系生命周期完善                                                            | 推荐可解释/可反馈；关系与媒体成本、留存可量化                                           |

第 0/1 批 UI 可先在本地开发，但**不能在服务器迁移完成前把新 Worker 推向生产**。当前生产 Market D1 比 `develop` 迁移落后；已有一条旧多人场景数据按用户要求备份并删除，仍须核对迁移账本，按顺序补齐 schema、验证触发器及旧客户端拒绝路径。上线前还要处理删除内容在其他数据库中的关联计数，并演练备份/回滚。任何生产迁移或发布均按[部署规范](deploy.md)与[平台发布规范](platform-release.md)执行；本地完成、测试通过不等于线上可用。

## 七、统一验收清单

1. **界面**：手机与宽屏的会话、联系人、Market、设备和设置有清晰层级；文案不堆叠，字号一致；“我的”正常打开；旧入口可定位到新位置。
2. **数据**：同一卡被两个用户导入形成两个私有实体；角色可改名并持续记忆，场景没有个人关系记忆；旧卡、旧聊天迁移有计数与回读校验，刷新和另一终端可继续；Android 未读计数指向正确聊天，登出后不再显示旧账号未读。
3. **隔离与安全**：账号、角色、真人聊天、群的记忆和权限逐层验证；共享需显式开启；设备断开/未授权时不能输出，停止不受阻；主动消息不执行设备工具。
4. **执行与费用**：假工具结果、重试、断线、超时和取消均有真实状态；没有工具 trace 就不展示已完成；同一请求只结算一次，失败释放预留。
5. **运营**：Market 角色/场景/波形发布与审核、收藏/关注、举报；支付订单/退款/账本对账；创作者仅获站内 Credit；上线前跑完整测试、跨端与预发迁移演练。

Avatar/AR 留在后续候选清单，本轮不为它设计阻塞性的接口或专门排期；公开及个人头像、情境图片和语音仍按前述批次实施。

当前 `develop` 已有统一消息、服务器会话、角色编辑/头像、部分记忆与主动消息、Market 类型化、Agent 工具结果校验等**局部实现**。个人卡片浏览器缓存已按账号隔离，旧版无归属的本地卡片需明确导入；仍须验证跨端与失败恢复。Agent 的服务端 `TaskRun` 与一次性工具调用领取已在本地接线；创建窗口持有内存执行令牌，同账号其他窗口只能查看运行、不能追加新工具调用。托管文字模型的多次请求可按 TaskRun 归集费用，每次请求仍独立预留与结算。未知、拒绝、失败或仍在处理的设备工具结果不再交给模型自由总结，后续普通设备工具暂停，停止工具保留安全执行入口。断线后的未知结果会保守标为待核对；这些客户端报告不能证明设备操作真的完成，仍需在设备执行 owner 边界完善可信收据、续跑和费用联动。生成图片/视频任务现在显示在 Agent 私聊时间线，媒体任务本身仍由服务器单独保存；Video 摄像头理解已有托管 Credit 路径，按可信实际用量结算，缺失用量会进入待核对。真实服务商响应与跨端媒体呈现仍待验收。以上都需按上表端到端验收；正式在线支付和生产迁移仍是未完成工作。不得用 UI 展示或单元测试通过代替完整交付。
