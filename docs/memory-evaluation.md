# 私人记忆检索评测（合成数据基线）

本评测只使用代码里编写的虚构中文对话与人物，不读取本地账号、`Private/`、生产 D1 或用户聊天。
它是诊断用例，不是中文语义记忆达标声明。运行方式：

```bash
npx vitest run workers/auth/src/memory-evaluation.integration.test.ts --reporter=verbose
```

输出中的 `MEMORY_EVAL` 单行 JSON 可供脚本收集。测试使用真实 SQLite 执行 Auth 的所有迁移，
从带身份验证的 `/api/auth/memory-context` 入口读取，而不是直接调用排序函数。固定语料包括：
账号 Alice/Bob、Alice 的两个私人关系、同一关系的两段会话、独立的真人私聊/群聊标记会话，
用户与助手消息，以及 14 条已确认记忆（含别名、同名、否定、前后矛盾、约定、账号级和异作用域事实）。
另外调用 0047 的跨会话分段候选链路验证“待核对 → 确认 → 来源修改/删除撤除”。
所有名字、日期与内容均为合成，不对应真实用户。

## 评分与复现结果

30 条固定问题分别给出预期 Top1、必须同时进入当前层前 8 的候选集合，或预期空结果。
“张伟会弹吉他吗”没有部门，要求两个同名人物的记录都出现，不能把最新的一条当成正确答案。
“林然面试哪天”要求别名说明和事件都能召回；“小陈面试哪天”在当前关系没有来源，要求空结果。
这衡量的是**检索候选**，不代表最终 AI 回答正确。测试强制跨账号、跨关系、默认关闭的账号记忆、
助手猜测不得泄入；这些安全断言失败会使测试失败。质量题允许报告失败，防止用修改期望掩盖缺口。

在 2026-09-30 当前 `develop` 的 D1＋本地关键词/双字片段排序上，30 题通过 **29 题**。检索现在忽略更多问句填充词，且查询中未在候选资料出现的跨词双字片段不再获得高于真实匹配词的权重；“猫是我养的吗”这类倒装养育问题只匹配明确以“我养／我没养同一对象”陈述的来源，不把朋友养宠物的记忆归给用户。仍保留足够的覆盖率门槛，避免已删除的别名关系仅靠共同话题词重新关联：

| 类型           |    通过/总数 | 观察                                                                                 |
| -------------- | -----------: | ------------------------------------------------------------------------------------ |
| 直接跨会话事实 |          5/5 | 明确提到小林/小王与事件时可召回                                                      |
| 别名           |          2/3 | 别名原文可见；未明确建立人物链接时，跨事实关联仍可能漏召回                           |
| 同名与未知人物 |          7/7 | 无部门的张伟问题保留两位候选，仍需回答层澄清                                         |
| 否定与改写     |          6/6 | 倒装养育问题可召回明确第一人称来源；检索到否定句不等于模型一定正确理解否定           |
| 前后纠正       | 4/4 候选可见 | 旧咖啡偏好和新“不喝咖啡”仍同时有效；**纠错解决率 0/1**，不能把候选可见当成冲突已解决 |
| 约定与旅行     |          5/5 | 当前固定题集召回；更多独立语料仍需验证                                               |

另有十条额外合成问题：五条验证“狗是我养的吗”的两种问法、朋友养鸟／乌龟不得冒充本人、跨账号的养鱼不能泄入；五条验证陈宁同名不同部门、睡眠时间前后变化。两组各 5/5，且手工把旧睡眠事实标记为被新事实替代后，旧事实不再召回。它们是在这次改动期间新增的稳健性样本，**不算未见过的独立留出集**。倒装规则只覆盖 1–2 字对象和显式第一人称“养”来源，不推断“帮朋友养”、省略主语或其它动作。这是窄范围词法修复，**不是普遍的中文反问理解能力**。

删除传播、关系/账号隔离、账号记忆开关在测试中通过。来源消息变更会清空原子记忆和已确认的跨会话
分段摘录，并保留墓碑；助手对面试结果的猜测从未成为记忆。这些是本地 SQLite/路由级证据，
**没有验证真实 Chat 群成员 ACL、跨服务部署顺序、备份删除或线上并发**。

明确建立人物及其别名关联后，定向回归还检查了同名消歧：“产品组张伟”只召回产品组已关联事实，
“财务组张伟”只召回财务组事实；只问“张伟”或同时询问两人仍保留两个候选。较长别名优先只
作用于用户显式关联的人物，不能自动识别未整理的同名人物；上表 29/30 是未结构化检索的固定题集结果。

另有与原固定题集分开的虚构中文留出集，运行
`npx vitest run workers/auth/src/memory-evaluation.heldout.test.ts --reporter=verbose`，
检查别名人物的未知住址、生日、饮食问题应拒答，已知画展和别名应召回，旧茶偏好被显式替代后
不得出现，以及跨关系/账号不泄露。初测 **7/12**：已链接人物被当作任何主题都相关，未知问题
会带出画展和别名资料；未链接“小许生日”也误带出爬山计划。检索现将人物匹配只作为范围线索：
有明确主题词时，需要该人物至少一条资料提及该主题；别名来源仅在主题有证据或询问姓名时
补充引用。相同 12 题复测 **11/12**。剩余“我现在喝什么茶”漏召回，因为“我喝茶”与
“我现在改喝绿茶”没有连续双字词重合。新增保守的第一人称动作／短对象匹配后，扩充朋友偏好、
替朋友买茶、朋友转述、无关茶资料、旧事实替代、过去／现在时态以及养猫的独立反例，当前
**15/15**。该匹配只适用于“我［时间］喝／吃／养什么［一至二字对象］”及以第一人称直接陈述
相同动作、时态和对象的来源；朋友的行为即使包含同一关键词也不入选。原固定集仍为 29/30，
显式建立别名/纠错后可比题为 28/28。它不能泛化到任意省略、跨词语义同义或他人代述，
也未验证模型最后的回答是否拒答；这些题已经参与本轮修复，**不再是未见过的留出集**，
不能把 15/15 解读为真实中文对话准确率。

## 延迟与费用口径

每题先进行 5 次预热查询，随后重复 5 次，合计 150 次本机内存 SQLite 读；计时范围是完整
`handleMemoryContext` 调用与 JSON 读取，包括会话、关系、D1 权限复核。最近一次运行的本机
P50 **0.181 ms**、P95 **0.278 ms**，每次 **7** 条 SQL prepare（2026-09-30 本机一次运行）。这里没有网络、Cloudflare
Worker 调度或真实 D1 尾延迟；数值只可用来对比同一机器与同一评测脚本的后续改动，不是生产 SLA。
`fetch` 被测试替身设为失败，实测额外 provider 调用 **0**，因此额外检索 provider 费用是
**0 USD / 1000 次读**；这不包括 D1/Worker、现有聊天模型或自动记忆抽取成本。托管 Mem0、
Mem0 OSS、向量索引和任何 embedding/rerank 的 P95、每千轮费用、中文质量都**尚未实测**。

## Mem0 与可替换检索层的门槛

[Mem0 官方流程](https://docs.mem0.ai/core-concepts/how-it-works)区分写入时抽取与读取时检索，
强调 `user_id`、`agent_id`、`run_id` 等范围过滤；其托管平台融合语义、关键词、实体和时间信号，
OSS 依赖配置的向量库与可选重排器，能力不能视为相同。官方文档也说明自动抽取可叠加新事实，
纠错与删除仍需要显式操作。使用托管 API 需要密钥并发送内容；OSS 默认组件还需要模型、embedding
与存储配置。当前没有任何 Mem0 账号、密钥、服务或 SDK 接入。

下一步应先扩充未用于调参的中文多会话样本和人工标注，纳入实体别名、同名、现实/剧情、否定、
时间纠正、删除及各聊天作用域，再以同一题集对比 Mem0 Platform、OSS 和 Cloudflare 方案。
对比必须同时记录 Top1、Recall@8、缺省拒答/追问、纠错传播、跨作用域泄露次数、P50/P95、
每千次写入与读取的模型/存储费用、导出和迁移难度。任何候选系统都只能在 D1 已授权的最多 200 条
记忆中建议排序或返回 ID；最终注入前必须回到 D1 复核 owner、关系、逐聊天开放、确认状态、
来源、到期及墓碑。向量/托管索引的过滤器只是缩小搜索范围，不能替代这些授权与删除判断。
上传私人原文给新服务商还需单独的用户选择、数据保留政策、预算和失败回退设计。

目前固定题集 29/30，但未显式链接的别名关联仍漏召回，更多独立问法和错误召回尚未充分测量，冲突也未自动解决。证据**不支持直接接入 Mem0 或仅凭当前分数宣布完成**。
先保留现有 D1 权威读写和保守关键词回退；可替换召回接口在外部候选的中文质量、隐私与成本实测后再定型。

## 长对话压缩的落地边界

压缩是**会话上下文**，不是经确认的用户事实。完整消息继续留在服务端原始会话中并按页展示；
模型输入保留近期完整轮次，再加入一份可追溯、按会话递增的旧段摘要。摘要不能替换原文，
不能自动成为跨会话的长期记忆，也不能包含工具调用的“已成功”推测。角色关系中的中长期记忆
仍由当前 `personal_memories` 与来源、确认状态、纠错、删除规则管理；场景没有自己的私人记忆。

Auth D1 已有独立的 `conversation_digests` 表和精确会话版本／摘要版本／来源游标写入边界；
来源消息编辑、删除、插入到已压缩区间或角色身份变化会撤销摘要。读取时再次核对当前私人关系，
客户端只以“可能有误的会话概述”注入模型上下文。独立的角色关系开关默认关闭，明确告知会把
较早的**双方文字消息**发给 MiniMax；它与只分析用户消息的长期记忆候选开关分开。分钟任务
每轮最多处理 16 条已离开最近 20 条窗口的消息，以旧摘要和新增原文生成下一版；写入时逐条
核对给模型的来源片段、会话版本、关系、摘要版本与授权版本；一次请求中关闭再开启也不能
复用旧授权。模型返回空概述时只推进来源游标，不向对话注入空内容，也不重复计费同一段。
失败退避后重试，不能在
生成失败时假装摘要已更新。模型提示将摘要标为“可能不完整的历史对话概述”，用户当前纠正和
已确认的角色记忆优先。设备动作、授权和工具执行结果只能取实时状态与收据，不取摘要。

此设计借鉴 [LangMem 的增量摘要](https://langchain-ai.github.io/langmem/guides/summarization/)：
它把完整 UI 历史和给模型的摘要上下文分开，并用 running summary 避免每轮重新摘要全部消息。
[Mem0 的写入与作用域模型](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/memory-operations/add.mdx)
可作为候选检索层参考，但不能接管当前 D1 的确认、范围与删除权威。上线验收需要覆盖：超长会话
增量压缩与分页原文一致、双端并发不跨游标、来源修改/删除后旧摘要不可注入、同名人物和否定
不被总结反转、跨账号/关系/群隔离、失败回退仍能用近期原文对话，以及每千轮真实费用与延迟。
这只保证摘要的来源与作用域，不保证模型概述的语义正确；同名人物、否定、长期纠错和真实
MiniMax 延迟／费用仍需预发评测。现有“用户原文摘录”也不能当作已确认的长期事实。
