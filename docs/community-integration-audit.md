# 真人社群与 Market 接入审计

这是 [AI 陪伴升级提案](companion-platform-plan.md) 的实施补充。以下按当前代码核对；除文末列出的窄修复，其余均是待实施设计，不表示服务端记忆或多人 AI 已完成。现有管理页面、设备连接和 owner-side 执行链保留。

## 已有资产与真实缺口

| 能力                  | 现有实现                                                                                             | 最小改造接缝                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 真人私聊、公开/私密群 | `apps/chat` 的 RoomDO、LobbyDO、WebSocket、R2；Auth 短期票据、联系人及互关私聊                       | 在现有会话列表增加 AI 会话；不另建真人聊天产品                                                            |
| 群 AI                 | `use-room-agents.ts`：一个固定 `ai:room`，被 @ 才响应、最近 20 条消息、host 浏览器执行               | 先恢复主站现有人设编辑入口，再迁移到服务端幂等执行；多 AI 放在下一次协议版本                              |
| 人设复用              | `RoomAgentDialog.tsx` 从共享 `@0xnullai/scenes` 库复制 name/prompt                                   | 保留手动编辑，引入公开角色版本引用及群内昵称；私人关系不复制到群                                          |
| Market                | `schema.ts` 的 waveform/scenario/multi-scene；上传、批量导入、搜索、所有者编辑/删除、管理员隐藏/恢复 | 新增 character 类型与对应 payload 校验，复用已有上传/详情/编辑/审核流程                                   |
| 多人剧本              | Market 已保存 setting、roles、aiPlayable、aiMode、playerCount                                        | Chat 已移除旧 scene/role 协议，不能把 Market 的多角色选项当作已实现的多 AI 群；需明确的“角色加入群”新映射 |
| 语音和图片消息        | Chat `ChatMedia`/wire `MediaRef` 支持 image/audio，R2 有会话上传能力                                 | 新增生成媒体、转写、工具结果消息块与 jobId；视频和实时通话不是已有 audio 消息的同义词                     |
| 历史                  | RoomDO SQLite 已存聊天，R2 存附件；`GROUP_MESSAGE_LIMIT=1000`，七天无连接回收群及内容                | 新的长期群必须采用显式保留策略和分页历史；不能把仅最近 1000 条称为永久云记录                              |
| 创作者回报            | Market 下载奖励走 Auth `rewardMarketDownload`，详情已有 Credit 打赏                                  | 继续只发 Credit，用统一账本消费 AI；无提现、银行信息、现金结算或提现管理页面                              |

主站此前用 `!inShell` 同时隐藏房间 AI 唯一按钮和对话框，且 Web/Android 无替代入口；群 AI 逻辑存在，但统一网站中无法添加或编辑。这是本轮先修复的可见断点。

当前群 owner 与 AI host 不同：owner key 决定配置权限，host 是在线执行者、离线会转交其他在线浏览器。不能按当前 host 的模型凭据或账户余额默认决定未来群 AI 付费人。Chat 私聊明确拒绝 agent/group 帧，因此私聊邀请 AI 必须有独立的参与者同意与权限迁移，不能直接取消这条保护。

## 角色与个人内容的边界

公开角色保存在 Market，包含版本、创作者、简介、人设、开场白、示例对话、标签、声音/形象偏好、许可和来源。用户导入后在个人内容中保存引用或私有副本，并可编辑专属名字、称呼、关系偏好和记忆。Market 发布接口只接受公开角色字段，不能把个人 memory、relationship history、聊天或朋友圈关系序列化进角色卡。

现有 scenario 是兼容入口：短期仍可把公开角色的可移植人设导入场景，再用现有群 AI 对话框加入群；它不等于完整角色实体。外部卡字段、世界书或大 prompt 不能直接塞入群的 4000 字人设字段。保留原始卡与来源，提供显式的群版人设编辑；后续按预算检索世界书内容，避免盲目提高每轮上下文成本。

作者修改 Market 条目后应生成新版本，用户选择是否更新公开设定；不得覆盖用户起的 AI 名字、私人关系或群昵称。管理员沿用现有入口处理公开内容；不能因拥有 Market 管理角色就自动获得用户私聊/私人记忆读取权限。

## Memory 进入真人社群的规则

| 范围                   | 可读取内容                                           | 写入与共享规则                                                           |
| ---------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 用户与某角色的私人关系 | 本人会话、自己确认的事实、关系事件、短中长期记忆     | `userId + relationshipId` 隔离；本人可查看、纠正、删除；群调用默认不可读 |
| 群共享记忆             | 该群允许 AI 读取的消息、群内明确共享的人物/事件/约定 | `groupId` 隔离，来源 messageId/参与者/可见范围可追溯；提供群内记忆管理   |
| 个人对群的私有笔记     | 本人手动记录或从有权访问的群消息明确保存的内容       | 只在个人内容中显示；不自动反向写入群记忆                                 |
| 公开角色设定           | 发布的角色版本、获授权世界书                         | 可跨会话复用；不包含其他用户私人记忆                                     |

检索前服务端校验当前成员、会话、记忆 scope、来源可见性和删除状态。向量检索后再次过滤，不依赖 prompt 告诉模型“不要泄漏”。新成员是否可看旧历史应是明确的群设置；退群或被移除后立即失去检索权。消息/账户删除同步处理摘要、关系事件和向量索引，不能删除原文后继续从衍生记忆恢复。

真人私聊/群聊的私人账号记忆现由 Auth 的 `0046_human_memory_shares.sql` 和
`/api/auth/human-memory/*` 单独授权：账号、具体会话、具体记忆三重绑定，默认关闭，接收者读取时
通过 Chat 的权威群成员摘要或 Auth 的实时私聊关系再核验。授权仅引用原记忆 ID，纠正、删除、
撤销后不再投影旧正文；群成员版本变化、私聊断联或删除线程使旧授权失效。接收者只取得显示所需字段，
来源 AI 会话标识不外泄。这是给真人展示的选择性共享，不代表群 AI 已获得群记忆检索能力，
也不改变各 AI 私聊的 `account-memory-access` 开关。

短期为当前会话窗口，中期为带来源的阶段摘要/未完成事项，长期为可编辑事实，relationship history 为独立事件时间线。群内按稳定账户身份关联说话者，不按 displayName 或临时 peerId 合并人物；用户谈到的朋友是用户陈述的人物记录，不自动读取联系人私聊或其他人的朋友圈。群共享记忆与私人记忆分开存储和授权，可复用相同抽取/检索实现。

主动聊天分为用户私聊提醒和群内主动话题：分别设置开启、时区、安静时段、频率、暂停、退出。群主动发言须群 owner 配置及成员可知，私人主动消息须本人开启；同一事件去重、额度不足停止。主动聊天不等于自动授予设备权限，也不能在后台恢复设备输出。

## 多模态、工具与 Credit 如何进入原 Chat

继续沿用 ChatPanel 消息流，扩展有类型的内容块：文字、音频/转写、图片、视频、工具确认与结果。发送用户媒体与 AI 生成媒体共用可见范围，但不共用“付费成功”的判断。群语音、情境自拍、视频生成都记录角色/会话/jobId，完成后回写同一条消息；刷新和换端可以恢复状态。

建议由统一服务端 AI 入口完成鉴权、模型路由、预算预留、任务调度、用量结算和失败返还。现有 RoomDO 继续负责真人消息和在线广播；推理 job 从前端 host 迁出，使用 messageId + agentInstanceId 幂等，避免 host 转移、重连和并发 @ 重复收费。可接受协议不同的语音/WebSocket 适配器，共享的是账户、会话和账本，不强行把所有媒体请求变成同一 HTTP 调用。

群 AI 指定明确 payer 和预算：首期可采用 owner 开启预算；成员触发前可看到是否消耗自己或群主 Credit。禁止自动扣当前 host、随机在线成员或被 @ 者余额。创作者的下载奖励、打赏或未来分成都写 Credit 账本，不产生可提现余额。设备工具继续经当前 owner-side 精确身份、租约、同意、安全限值和停止路径执行，AI 服务端只提交请求。

搜索、文件理解、提醒、计划、多步骤工具可作为同一角色在私聊/群聊的能力，但群成员可见性和执行授权独立于人设。外部卡、世界书、群消息和工具结果均是内容，不能提升权限；真正执行前向有权授权的人确认所需权限。

## 按依赖实施，避免重做界面

1. 恢复现有主站群 AI 入口，阻止超长角色内容静默截断；保留当前 Market 和管理页面。
2. 建立服务器会话、角色版本、私人关系、群成员和消息标识；云历史分页/保留策略优先于自动记忆。迁移旧历史须上传校验并回读后再清理本地副本；旧 room owner key 单独处理，不因禁止本地聊天记录就删除设备/身份所需状态。
3. 统一 AI job 与 Credit：先文本群 AI，再接已有 Voice/Video 协议适配；完成错误补偿、预算上限、重放和并发测试。
4. 角色卡在 Market 发布/编辑/精选，与个人库及群加入互通；个人名字与关系保持稳定。精选卡只引入有明确再分发许可的素材或自有原创卡。
5. 服务端私人与群 scope 记忆，接短/中/长期、关系时间线、个人朋友圈叙述和主动对话；最后开放多 AI 群、群媒体生成和工具扩展。

每批验收除正常使用外，必须覆盖：非 owner 不可改群角色、被移除成员不能读群历史/记忆、角色发布不能泄漏私密 memory、作者更新不覆盖个人命名、同一 job 不重复扣费、host 断线不重复答复、被删除来源不再被检索、设备拒绝不影响停止。

## 本轮实际修改与局限

- 统一网站恢复群 owner 的“房间 AI”入口，复用原对话框；普通成员与真人私聊不显示入口，对话框也受相同条件限制。
- 场景库导入的完整名字和人设保留在可编辑表单；超过当前 40/4000 字上限时明确提示并禁止保存，不改原场景。
- Worker 对直接发送的非法/超长 Agent 配置返回 `agent-error`，保留既有配置，不再静默截断；原有 owner 校验不变。该错误帧主要是协议反馈，旧客户端可能不展示它；本轮当前 UI 会在发送前阻止超长内容。
- 回归测试覆盖主站入口、非 owner/私聊不可达、导入后编辑保存和服务端拒绝/合法边界。

尚未部署、未改数据库、没有实际设备验证。长期记忆、服务器 AI 执行、多模态统一扣费和长期群保留策略仍需后续批次实现。
