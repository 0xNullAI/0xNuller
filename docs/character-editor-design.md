# 角色卡、个人实体与在线编辑器

此设计用于网站改版的分批验收。**角色和场景都是公开 Prompt 卡，但身份不同**：两者共用 Market 的 `scenario` 存储和名称、Prompt、版本、编辑器，`content.kind` 固定为 `character` 或 `scene`。角色有公开人设和头像，可被每位使用者实例化为自己的长期关系；场景只有环境与规则，不拥有独立关系或记忆。旧结构化卡按角色读取，旧 prompt-only 卡按场景读取，历史正文和版本号不改。已发布卡不能切换类型，转换须新建卡。`multi-scene` 已退出发布与展示，由 `0013` 迁移删除及禁止写入；真人群聊保留。波形是设备内容，不属于 Prompt 卡。

角色路径：Market 发现角色 → 详情预览 →「开始聊天」→ 当前账户建立/复用私有关系 → 统一聊天收件箱。场景路径：发现场景 → 保存为可复用环境 Prompt；它不触发「开始聊天」或关系创建。创作路径：发现页分类行右侧「创建」→ 角色／场景编辑器或波形发布 → 账号私有草稿 → 明确发布。私人称呼、头像、关系和记忆在聊天设置中管理，不进入公开卡。真人和群可以分享公开卡链接，但不能分享私人实例或记忆。

## 对象与身份

| 对象           | 身份与归属                                          | 内容                                                                        | 更新规则                                                     |
| -------------- | --------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 公开 Prompt 卡 | Market item ID，作者账户                            | 名称、基础 Prompt、可选场景设定/人物资料/开场/示例/标签/署名/许可和公开头像 | 每次发布递增 revision；旧版留档。使用者手动预览和采用新版    |
| 在线草稿       | 作者账户 + `new` 或 item ID                         | 正在编辑的公开字段、可选外部 JSON 和私有容器文件 ID                         | 服务端保存，版本冲突拒绝覆盖；草稿不进公开目录               |
| 个人实体       | 使用者账户 + 稳定角色 ID 对应的私有 relationship ID | 我给 AI 的名字、AI 对我的称呼、关系类型、共同约定、私人外观                 | 角色卡更新不重建实体，不清空其聊天与记忆                     |
| 聊天           | conversation ID + participant/relationship ID       | 真人私聊、AI 私聊、群聊的服务器消息                                         | 同一聊天列表与消息样式；调用 AI 时仍用服务端参与者和权限判断 |
| 记忆           | 使用者账户 + relationship/conversation/group 作用域 | 中期摘录、经确认的长期事实、关系历史、人物/事件                             | 来源可查、可纠正与删除；群与真人只看到明确共享的部分         |

默认一个账户对一张公开卡建立一段持续关系。多个账户导入同一张卡时得到不同 relationship ID，称呼、头像、记忆、Credit、设备授权完全隔离。若以后允许同一账户为同一角色建立“平行关系”，必须新建明确的 relationship ID，不能仅靠改名复制。

当前实现已在公开内容中标注 `kind`，旧版以是否有有效结构化人物字段推断。Agent 对场景不读角色关系、记忆或主动消息工具；Voice 场景通话也不绑定角色关系，仍保存服务器聊天历史。**仍缺少同一会话中的角色＋可选场景叠加**：现有文本与语音各选一份 Prompt，后续需增加会话级 `characterId` 与可选 `sceneId`，组装人设和场景规则；记忆只按角色关系检索。Video 须沿同一选择与权限边界。旧会话按原卡类型迁移，不把旧纯场景会话自动转为角色关系。

公开卡只声明可移植的人设：`name`、基础 `prompt` 必填，公开头像、简介、标签、开场白、性格、对话示例、作者/许可及来源均可选。作者可以改卡，但已使用该卡的用户保留已采用的人设版本；更新须由用户预览并主动采用。一个人的专属 AI 名字、私人头像、AI 对他的称呼、聊天、记忆与安全授权只能写入自己的关系/设置，不进入卡片版本、在线草稿或公开分享。创建个人实体时以稳定卡片 ID 建立关系；同名卡片不是同一个身份，卡片删除也不应静默删掉用户已有的私人关系与历史。

## 编辑器与用户路径

从 Market 分类行的「创建」或作者自己的详情「编辑」进入同一个页面式编辑器。首页只需名称、基础 Prompt；角色可增加结构化人物字段，场景仅保留环境规则和公开资料。右侧宽屏预览、窄屏顺排，持续显示公开内容，不显示私人关系或记忆。作者可手动保存在线草稿、恢复草稿、载入旧版本到编辑区，确认后才发布新版本。编辑冲突返回 409 并保留未提交内容。

编辑页沿用 Market 路径的 URL 参数，刷新或浏览器前进/后退后重新解析；已发布卡的编辑链接需要再次查询卡片和作者权限，不能因前端知道 item ID 就允许编辑。发布完成后转到公开详情链接。登录后停止输入约 1 秒即串行自动保存至账号，手动保存和发布复用同一队列；页面显示读取、保存中、已保存、暂停和冲突状态。草稿使用服务器 CAS revision，账号切换立即废弃原编辑器的写入资格；另一个设备更新草稿时不自动覆盖。草稿不会写进本机持久存储。刷新/关闭以及站内离页须提示仍未确认保存的修改，但浏览器原生离页提示并不保证一定展示。

发布是独立的明确动作：校验名称与基础 Prompt，展示最终公开字段与来源原件的发布状态，确认图片引用和当前 `expectedRevision`，再写入公开新版本。含私有容器文件的草稿会保留，供作者之后跨端下载原件；不含私有文件的草稿可在发布后清理。自动保存只是私有草稿，不会自动发布。作者发布新版本时，使用者的个人实体仍指向原版本，设置中提供差异预览和「采用更新」；拒绝自动改写已有人设、记忆或聊天。公开卡的编辑入口与个人实体设置入口保持分开，避免用户把私人称呼误发到 Market。

编辑区「试聊」使用临时草稿快照和真实托管文字模型，发送前显示价格与可用 Credit；预览不得写入个人实体的长期记忆、公开下载计数或其他用户的会话，也不授予工具、设备权限。模型回复和结算额必须来自真实接口，生产付费链路仍须单独验收。

外部 CCv2/CCv3 JSON 与 PNG/APNG、CHARX 内嵌的人物数据导入在该编辑器中完成：先限制文件和内嵌 JSON 的大小，校验 `spec`、`spec_version` 与名称，再把普通人物字段映射到可编辑的原生 Prompt/卡片。未知扩展留在原始 JSON，系统提示、后历史指令、角色书和资产引用只显示兼容提示，不作为平台指令、记忆或权限。原始 JSON 可下载；发布时默认仅发布已检查的人设投影，作者勾选并检查隐私与使用权后才公开原件。完整 PNG/APNG、CHARX 原文件保存在作者账户私有 R2 文件中，Auth 保存草稿引用前通过 Market 检查归属与文件存在；跨端可原样下载。容器不会自动成为公开资产，编辑后重新生成完整容器及角色书运行时检索列为后续互通阶段。

保存发布后，访客可浏览、收藏和分享公开卡；主站 Market 详情的「开始聊天」会重新读取当前可见卡，登录后为当前账户建立或复用私有 relationship，并选用该卡的人设快照打开新 AI 会话。首次消息才进入服务器聊天历史，空白会话不伪装成已同步记录；独立 Market 站点仍保留导入引导。角色公开卡更新提供预览与手动采用，保留私人 relationship ID。真人私聊可以分享公开卡链接；分享不会携带个人实体或记忆。群里的 AI 是明确加入的参与者，使用群内实例与昵称，只读取本群授权上下文，不继承任一成员的私聊记忆。聊天列表和消息组件对 AI、真人、群共用，消息的发送者类型与权限由服务器验证，卡片本身没有调用工具、操作设备或读取记忆的授权。

公开头像和私人头像是不同资产：作者可给公开卡上传或手绘默认图，使用者仍可在自己的实体设置里画或上传仅自己可见的头像。现有私人外观能力不自动发布。公开图使用独立 Market R2 资产、作者身份校验与版本引用；只有当前可见版本的图片供访客读取，旧版图片仅作者可预览，避免移除头像后旧链接继续公开。作者可从草稿移除并删除未被任何角色版本引用的图，D1 在最终发布写入时阻止引用已删除图。emoji 继续作为兼容回退。公开内容与生成媒体的审核、被替换素材的统一回收仍需完成。

## 记忆与模型上下文

模型输入按固定顺序组装：平台规则及工具策略 → 当前公开卡版本的人设 → 当前账户的个人关系与安全设置 → 按权限检索的记忆 → 当前会话消息 → 工具执行结果。公开卡的作者文本是低信任人物资料；工具调用必须由运行时执行并有结果证据，不能因角色卡写了“已调用”就报告成功。设备操作还要在最终执行边界检查物理身份、连接、许可与限额。

短期记忆是当前消息与真实工具结果；中期保存最近对话的可追溯摘录；长期保存用户确认或明确允许的事实；关系历史记录称呼、约定与共同事件。现阶段已有服务器消息、关系设置、关系范围的可编辑记忆及可选自动候选抽取，自动候选需用户确认后进入长期上下文。账号级记忆现在对每个 AI 聊天默认关闭，由用户在该聊天设置里单独开启；关系自身的记忆仍限该关系。权限核验失败不回退加载账号记忆。该关系的设置还可管理人物别名、把已确认事实关联人物并用新事实替换过时事实；叙事用的重要人物记录尚未自动同步到别名索引。跨会话抽象摘要质量、来源跳转和作用域可视化仍需进一步验收，真人聊天的记忆开放另走明确授权。

Mem0 只作为可替换的抽取和召回适配器评测；账号、消息、关系权限、事实来源和删除权威记录留在现有服务器。选型必须证明中文姓名、跨关系隔离、纠错/遗忘、延迟与成本优于现有 D1 加检索方案，不能把外部服务当作私人记忆的唯一副本。

## 分批验收

Market 导入在客户端和 Worker 共用解析器，校验 CCv3 的本地资产引用、路径、大小和被引用资产
的媒体签名。完整 PNG/APNG 或 CHARX 原文件以账号私有 R2 对象保存；草稿同步其受限 ID，跨端
恢复后可原样下载。公开卡不会获得私有原包或附件 ID，带未公开本地资产引用的原始 JSON 也拒绝
发布；公开素材仍只走作者明确上传的公开头像流程。编辑后重新生成完整容器、公开附属资产权限和
版本生命周期仍需单独实现。私有文件可由作者列出、删除，注销账户后 Market 分批清理 R2 对象。

1. **兼容基座（开发中）**：基础公开卡、在线草稿、版本历史、手动采用更新、个人关系、服务器记忆；CCv2/CCv3 JSON 导入与明确发布原件。验证旧 prompt-only 场景、Market 管理及设备路径不变。
2. **完整创作**：公开图像上传、草稿预览、手绘画板及真实托管试聊已实现；继续补角色质量评测、发布审核和未引用素材回收。完成真实第三方 JSON/PNG/CHARX 样本往返测试；不得未经许可预置第三方卡和头像。
3. **关系深化**：中期摘要、长期事实纠错/遗忘、人物与事件、记忆来源、跨端一致性、角色主动关心与通知。逐项验收真人群的上下文隔离。
4. **多模态与商业化**：角色语音、情境图片/视频和通用 Agent 任务回到同一聊天时间线，并通过统一 Credit 预留、结算和失败释放。创作者激励只发可消费 AI 的 Credit，无提现。

这些阶段是开发和验收顺序，不表示功能可忽略。生产迁移、真实服务密钥与上线须在本地及预发布验证后另行处理。

公开头像画板已接入 Market 在线编辑器：512 × 512 PNG，支持鼠标/触控、颜色、笔粗、橡皮、清空和最近 20 步撤销。笔画只留页面内存，预览并确认后上传至现有 Market portrait，沿用草稿 CAS、版本引用和受限素材清理。未确认笔画触发离页保护，并阻止直接发布；失败保留画板，账号切换撤销旧上传结果。emoji 与文件上传保留，未提供编辑已有图片、图层或服务端保存笔画。

已导入场景保存公开头像的受限 ID 引用，并随账户场景跨端同步；主动采用公开新版时才替换引用。聊天、语音和摄像头视图使用匿名公开读取作为默认形象，私人手绘/上传头像始终优先。下一次读取时，图片下架、缺失或格式不受支持均回退默认符号；已载入的当前页面不实时监听下架。公开图不复制到私人照片库；本地页面卸载或换卡时回收临时图片 URL。

草稿真实试聊已接入现有托管网关：读取实时目录和余额，显式付费发送，回复与已结算 Credit 来自真实接口。采用当前草稿名字/Prompt/人物设定与有限文字上下文，禁用工具、设备、私人记忆及正式关系/会话写入。试聊仅页面内存；修改草稿、关闭、离页、账号切换取消旧请求且不接收旧回复。首版仅托管文字模型、非流式、最多 6 轮和 512 输出 Token，不提供 BYOK、长期保存或质量评分。取消后已产生费用仍可结算，账本暂沿文本/Agent 类别；真实生产付费验收未在开发轮执行。
