## 已确定的产品边界

- 登录是应用入口；登录后以消息为首页。AI 私聊、真人私聊和真人群聊共用消息体验，手机参考 QQ 的层级，宽屏使用简洁的侧栏和聊天区。设置是列表与二级页面，Memory 放在设置中管理；移除左上角模式切换与各页面重复登录入口。
- 设备连接、权限、安全上限、租约与停止链路保持原有 owner 边界。Agent 以郊狼、负鼠等设备控制为重点；文件和任务工具可选择性加入，不得把模型的工具请求或文字陈述当作执行成功。
- Market 保留公开角色、场景和波形。角色与场景共用卡片发布基础设施，以明确类型区分：角色可在每个用户账号下独立实体化并拥有私有关系和 Memory；场景只提供环境／规则，可叠加到角色会话，本身没有长期关系或记忆。移除内置场景、多人场景和多角色 AI；真人群聊保留。
- Memory 是陪伴核心：近期消息、中期摘要、长期事实、关系历史分层；按账号、角色、会话及显式共享范围隔离。长对话不能无限追加原文。用户可更正、删除或关闭相应记忆。个人主页对已登录用户公开，但聊天、私人记忆、设备状态和非公开媒体不因此公开。
- 新聊天记录以服务器为权威来源，跨端同步；独立备份需覆盖 AI D1、真人 RoomDO 及 R2 附件。云端主存储不等于已验收备份。语音／视频应进入同一角色、场景、聊天与 Credit 语义。Android 需要推送。支付与 Avatar/AR 暂缓；创作者只获得站内 Credit，不做提现。

## 代码整理与提交顺序

先建立一个文件归属表：每个变更记录所属阶段、公共 API／数据影响、调用方、对应测试、文档和是否依赖别的阶段。阅读目标包 README、相邻测试和直接调用方后再编辑。优先修窄的共享 owner；跨功能语义放在 `packages/platform` 或 `packages/agent`，Web／Android 只组合，功能 app 不互相导入复用。删除旧入口前先确认旧数据和旧链接的兼容路径。

每阶段形成一个可审查的本地提交或少量紧密相关的提交：迁移与其消费代码同阶段，测试和文档随行为提交。使用按文件／按 hunk 暂存来隔开交织改动，先审查 `git diff --cached`；不要为了拆提交而改写已发布迁移、丢弃旧用户数据或制造暂时不安全的中间状态。Kit／MCP 的公开 API 变化按仓库规范添加 Changeset。现在的 `develop` 不是已推送的 `dev`；本 handoff 不授权推送、合并或发布。

## 检查节奏与交接报告

开发中运行受影响模块测试。一个阶段的代码冻结后，先构建共享依赖一次，再并发运行不互相写同一输出目录的 `npm run check:structure`、`npm run lint`、受影响测试和类型检查；全量测试与产品构建在阶段交付／最终集成时各跑一次。若命令共享构建产物，先后串行，不为追求并发制造竞态。只在修复导致代码变化或检查失败时重跑相应项。每个提交附上：行为变化、数据／权限／设备安全影响、执行的命令与结果、未运行的真机或服务验收、剩余风险和保留的用户工作。

下一位执行者应先完成阶段 0，给出文件归属与第一批提交的差异，再进入阶段 1。不要把本 handoff 中的“已有代码”当成已上线功能。
